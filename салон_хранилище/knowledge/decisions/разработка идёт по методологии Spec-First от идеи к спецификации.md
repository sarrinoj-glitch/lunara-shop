# Разработка идёт по методологии Spec-First от идеи к спецификации

Источник: `spec_driven_dev (1).pdf` в корне проекта.

**Принцип:** код не пишется, пока проект не описан полностью.

**5 слоёв:**
1. `PROJECT_IDEA.md`: проблема в цифрах, решение по шагам, аудитория, архитектура, монетизация, конкуренты, план запуска, риски
2. `SPEC.md`: для каждого модуля user stories, данные (типы как в SQL, RLS), API (метод, путь, тело, ответ, коды), экраны с 4 состояниями, бизнес-логика, крайние случаи
3. Генератор конфигурации: превращает спецификацию в файлы
4. Пакет: `CLAUDE.md` до 120 строк, `.claude/agents` (4–6 штук), `.claude/rules`, `.claude/skills`, `SPEC_TEMPLATE.md`, MCP (Context7 и Supabase)
5. Сборка субагентами: database-architect → backend-engineer → frontend-developer → qa-reviewer

**Важное:**
- писать конкретно, без абстракций и без TODO-заглушек
- на opus идут БД, безопасность и сложная логика, на sonnet UI и ревью
- у qa-reviewer нет Write/Edit
